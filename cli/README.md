# Paperclip은 업무에서 AI 에이전트를 관리하는 데 사용되는 앱입니다.

AI 에이전트 팀을 위한 오픈소스 오케스트레이션 플랫폼입니다.

**OpenClaw이 _직원_이라면, Paperclip은 _회사_입니다.**

Paperclip은 AI 에이전트 팀을 오케스트레이션하여 비즈니스를 운영하는 Node.js 서버 및 React UI입니다. 직접 에이전트를 가져와 목표를 할당하고, 하나의 대시보드에서 작업과 비용을 추적할 수 있습니다.

겉보기에는 작업 관리자처럼 보이지만, 내부에는 조직도, 예산, 거버넌스, 목표 정렬, 에이전트 협업 기능이 탑재되어 있습니다.

**풀 리퀘스트가 아닌 비즈니스 목표를 관리하세요.**

|        | 단계            | 예시                                                               |
| ------ | --------------- | ------------------------------------------------------------------ |
| **01** | 목표 정의       | _"$1M MRR을 달성하는 최고의 AI 메모 앱을 만들어라."_              |
| **02** | 팀 구성         | CEO, CTO, 엔지니어, 디자이너, 마케터 — 어떤 봇이든, 어떤 프로바이더든. |
| **03** | 승인 및 실행    | 전략을 검토하고, 예산을 설정하고, 시작하세요. 대시보드에서 모니터링합니다. |

## Paperclip이 적합한 경우

- ✅ **자율 AI 회사**를 구축하고 싶은 경우
- ✅ (OpenClaw, Codex, Claude, Cursor 등) **다양한 에이전트를 공통 목표**를 향해 조율하는 경우
- ✅ **20개의 Claude Code 터미널**을 동시에 열어두고 각각이 무엇을 하는지 파악하기 어려운 경우
- ✅ 에이전트가 **24/7 자율 운영**되기를 원하지만, 작업을 감사하고 필요시 개입하고 싶은 경우
- ✅ **비용을 모니터링**하고 예산을 강제하고 싶은 경우
- ✅ **작업 관리자처럼 느껴지는** 에이전트 관리 프로세스를 원하는 경우
- ✅ **스마트폰에서** 자율 비즈니스를 관리하고 싶은 경우

## Paperclip이 해결하는 문제들

| Paperclip 없이                                                                                                                        | Paperclip 사용 시                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ 20개의 Claude Code 탭이 열려 있고 어느 탭이 무엇을 하는지 파악할 수 없습니다. 재부팅하면 모든 것을 잃습니다.                      | ✅ 작업은 티켓 기반이며, 대화는 스레드로 연결되고, 세션은 재부팅 이후에도 지속됩니다.                                               |
| ❌ 봇에게 현재 작업을 상기시키기 위해 여러 곳에서 직접 컨텍스트를 수집해야 합니다.                                                  | ✅ 컨텍스트는 작업에서 프로젝트와 회사 목표로 자동으로 흐릅니다 — 에이전트는 항상 무엇을, 왜 해야 하는지 알고 있습니다.            |
| ❌ 에이전트 설정 폴더가 뒤죽박죽이고, 작업 관리·커뮤니케이션·에이전트 간 협업을 직접 다시 만들어야 합니다.                         | ✅ Paperclip은 조직도, 티켓팅, 위임, 거버넌스를 기본 제공합니다 — 스크립트 더미가 아닌 회사를 운영할 수 있습니다.                  |
| ❌ 루프가 폭주하여 무슨 일이 일어났는지 알기도 전에 수백 달러의 토큰이 낭비되고 할당량이 소진됩니다.                               | ✅ 비용 추적이 토큰 예산을 표시하고 한도 초과 시 에이전트를 제한합니다. 관리자는 예산으로 우선순위를 정합니다.                       |
| ❌ 반복 작업(고객 지원, 소셜, 보고서)이 있고 매번 수동으로 시작해야 한다는 걸 기억해야 합니다.                                      | ✅ 하트비트가 정기 작업을 일정에 따라 처리합니다. 관리자가 감독합니다.                                                               |
| ❌ 아이디어가 생기면 저장소를 찾고, Claude Code를 켜고, 탭을 열어 두고 직접 감시해야 합니다.                                         | ✅ Paperclip에 작업을 추가하면 됩니다. 코딩 에이전트가 완료할 때까지 작업합니다. 관리자가 작업물을 검토합니다.                       |

## Paperclip이 특별한 이유

Paperclip은 복잡한 오케스트레이션 세부 사항을 올바르게 처리합니다.

|                                   |                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **원자적 실행.**                   | 작업 체크아웃과 예산 강제는 원자적으로 처리되어 중복 작업도, 비용 폭주도 없습니다.                          |
| **영속적 에이전트 상태.**          | 에이전트는 처음부터 다시 시작하는 대신 하트비트 간에 동일한 작업 컨텍스트를 이어서 진행합니다.              |
| **런타임 스킬 주입.**              | 에이전트는 재학습 없이 런타임에 Paperclip 워크플로우와 프로젝트 컨텍스트를 습득할 수 있습니다.              |
| **롤백을 지원하는 거버넌스.**      | 승인 게이트가 강제 적용되고, 설정 변경은 버전 관리되며, 잘못된 변경은 안전하게 롤백할 수 있습니다.         |
| **목표 인식 실행.**                | 작업에 전체 목표 계보가 포함되어 에이전트가 제목뿐 아니라 "이유"도 일관되게 파악합니다.                    |
| **이동 가능한 회사 템플릿.**       | 시크릿 제거 및 충돌 처리를 포함하여 조직, 에이전트, 스킬을 내보내기/가져오기 할 수 있습니다.               |
| **진정한 다중 회사 격리.**         | 모든 엔티티는 회사 범위로 지정되어 하나의 배포에서 별도의 데이터와 감사 추적을 가진 여러 회사를 운영할 수 있습니다. |

### 구성 시스템

<table>
<tr>
<td width="50%">

**Identity & Access** — 신뢰된 로컬 또는 인증 방식의 두 가지 배포 모드, 보드 사용자, 에이전트 API 키, 단기 실행 JWT, 회사 멤버십, 초대 플로우, OpenClaw 온보딩. 모든 변경 요청은 행위자에게 추적됩니다.

</td>
<td width="50%">

**Org Chart & Agents** — 에이전트에는 역할, 직함, 보고 라인, 권한, 예산이 있습니다. 어댑터 예시는 다이어그램과 일치합니다: Claude Code, Codex, Cursor/Gemini/bash 같은 CLI 에이전트, OpenClaw 같은 HTTP/웹훅 봇, 외부 어댑터 플러그인. 하트비트를 받을 수 있다면, 채용된 것입니다.

</td>
</tr>
<tr>
<td>

**Work & Task System** — 이슈에는 회사/프로젝트/목표/상위 링크, 실행 잠금을 통한 원자적 체크아웃, 일급 블로커 의존성, 댓글, 문서, 첨부파일, 작업물, 라벨, 수신함 상태가 포함됩니다. 중복 작업도, 컨텍스트 손실도 없습니다.

</td>
<td>

**Heartbeat Execution** — 병합 기능이 있는 DB 기반 깨우기 큐, 예산 확인, 워크스페이스 해석, 시크릿 주입, 스킬 로딩, 어댑터 호출. 실행은 구조화된 로그, 비용 이벤트, 세션 상태, 감사 추적을 생성합니다. 복구는 고아 실행을 자동으로 처리합니다.

</td>
</tr>
<tr>
<td>

**Workspaces & Runtime** — 프로젝트 워크스페이스, 격리된 실행 워크스페이스(git worktree, 운영자 브랜치), 런타임 서비스(개발 서버, 미리보기 URL). 에이전트는 항상 올바른 디렉토리에서 올바른 컨텍스트로 작업합니다.

</td>
<td>

**Governance & Approvals** — 보드 승인 워크플로우, 검토/승인 단계가 있는 실행 정책, 결정 추적, 예산 하드 스탑, 에이전트 일시 중지/재개/종료, 완전한 감사 로그. 귀하의 승인 없이는 아무것도 배포되지 않습니다.

</td>
</tr>
<tr>
<td>

**Budget & Cost Control** — 회사, 에이전트, 프로젝트, 목표, 이슈, 프로바이더, 모델별 토큰 및 비용 추적. 경고 임계값과 하드 스탑이 있는 범위 지정 예산 정책. 초과 지출 시 에이전트가 자동으로 일시 중지되고 대기 중인 작업이 취소됩니다.

</td>
<td>

**Routines & Schedules** — cron, 웹훅, API 트리거를 사용한 반복 작업. 동시성 및 따라잡기 정책. 각 루틴 실행은 추적된 이슈를 생성하고 지정된 에이전트를 깨웁니다 — 수동 시작이 필요 없습니다.

</td>
</tr>
<tr>
<td>

**Plugins** — 외부 프로세스 워커, 기능 게이트 호스트 서비스, 작업 스케줄링, 도구 노출, UI 기여를 포함하는 인스턴스 전체 플러그인 시스템. 포크 없이 Paperclip을 확장할 수 있습니다.

</td>
<td>

**Secrets & Storage** — 인스턴스 및 회사 시크릿, 암호화된 로컬 스토리지, 프로바이더 기반 객체 스토리지, 첨부파일, 작업물. 민감한 값은 범위 지정 실행이 명시적으로 필요한 경우를 제외하고 프롬프트에 포함되지 않습니다.

</td>
</tr>
<tr>
<td>

## Paperclip이 아닌 것

|                              |                                                                                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **챗봇이 아닙니다.**          | 에이전트에게는 채팅 창이 아닌 직무가 있습니다.                                                                       |
| **에이전트 프레임워크가 아닙니다.** | 에이전트를 만드는 방법을 알려주지 않습니다. 에이전트로 구성된 회사를 운영하는 방법을 알려줍니다.               |
| **워크플로우 빌더가 아닙니다.** | 드래그 앤 드롭 파이프라인이 없습니다. Paperclip은 조직도, 목표, 예산, 거버넌스를 갖춘 회사를 모델링합니다.       |
| **프롬프트 관리자가 아닙니다.** | 에이전트는 자체 프롬프트, 모델, 런타임을 가져옵니다. Paperclip은 에이전트가 일하는 조직을 관리합니다.            |
| **단일 에이전트 도구가 아닙니다.** | 팀을 위한 도구입니다. 에이전트가 하나라면 Paperclip이 필요 없을 수도 있습니다. 스무 개라면 — 분명히 필요합니다. |
| **코드 리뷰 도구가 아닙니다.** | Paperclip은 풀 리퀘스트가 아닌 작업을 오케스트레이션합니다. 자체 리뷰 프로세스를 활용하세요.                    |

## 빠른 시작

오픈소스. 자체 호스팅. Paperclip 계정 불필요.

```bash
npx paperclipai onboard --yes
```

이 빠른 시작 경로는 이제 가장 빠른 첫 실행을 위해 신뢰된 로컬 루프백 모드로 기본 설정됩니다. 대신 인증/프라이빗 모드로 시작하려면 바인드 프리셋을 명시적으로 선택하세요.

```bash
npx paperclipai onboard --yes --bind lan
# 또는:
npx paperclipai onboard --yes --bind tailnet
```

이미 Paperclip이 설정되어 있는 경우 `onboard`를 다시 실행하면 기존 설정이 유지됩니다. 설정을 편집하려면 `paperclipai configure`를 사용하세요.

또는 수동으로 설치:

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

API 서버가 `http://localhost:3100`에서 시작됩니다. 임베디드 PostgreSQL 데이터베이스가 자동으로 생성됩니다 — 별도 설정이 필요 없습니다.

> **요구 사항:** Node.js 20+, pnpm 9.15+

## 자주 묻는 질문

**일반적인 설정은 어떻게 생겼나요?**
로컬에서는 단일 Node.js 프로세스가 임베디드 Postgres와 로컬 파일 스토리지를 관리합니다. 프로덕션에서는 자체 Postgres를 지정하고 원하는 방식으로 배포하세요. 프로젝트, 에이전트, 목표를 설정하면 — 에이전트가 나머지를 처리합니다.

솔로 창업자라면 Tailscale을 사용하여 이동 중에도 Paperclip에 접근할 수 있습니다. 이후 필요할 때 Vercel 등에 배포할 수 있습니다.

**여러 회사를 운영할 수 있나요?**
네. 하나의 배포로 완전한 데이터 격리를 갖춘 무제한 수의 회사를 운영할 수 있습니다.

**Paperclip은 OpenClaw이나 Claude Code 같은 에이전트와 어떻게 다른가요?**
Paperclip은 그런 에이전트들을 _활용합니다_. 조직도, 예산, 목표, 거버넌스, 책임감을 갖춘 회사로 에이전트들을 오케스트레이션합니다.

**OpenClaw을 Asana나 Trello에 연결하는 대신 Paperclip을 사용해야 하는 이유는 무엇인가요?**
에이전트 오케스트레이션에는 작업 체크아웃을 누가 담당하는지 조율하는 방법, 세션 유지 방법, 비용 모니터링, 거버넌스 수립 등 미묘한 부분들이 있습니다. Paperclip이 이것을 대신 처리해 줍니다.

(자체 티켓 시스템 연동은 로드맵에 있습니다)

**에이전트는 계속 실행되나요?**
기본적으로 에이전트는 예약된 하트비트와 이벤트 기반 트리거(작업 할당, @-멘션)로 실행됩니다. OpenClaw 같은 연속 에이전트를 연결할 수도 있습니다. 에이전트를 가져오면 Paperclip이 조율합니다.

## Paperclip Cloud Sync

클라우드 업스트림 동기화는 `Cloud Sync` 실험적 설정 뒤에 있습니다. 푸시하기 전에 인스턴스 설정에서 활성화하세요.

```bash
paperclipai cloud connect https://your-stack.paperclip.app
paperclipai cloud connect https://your-stack.paperclip.app --no-browser
paperclipai cloud push --company <local-company-id> --dry-run
paperclipai cloud push --company <local-company-id>
```

`cloud connect`는 로컬 인스턴스를 대상 스택에 대해 인증하고 업스트림 토큰을 로컬 인스턴스 시크릿 저장소에 저장합니다. 기본 경로는 동의를 위해 브라우저를 열며, `--no-browser`는 디바이스 코드 플로우를 사용하여 인증 URL과 사용자 코드를 출력합니다.

`cloud push --dry-run`은 선택된 로컬 회사를 내보내고, 연결된 Cloud 스택에 미리보기 번들을 전송하며, 충돌 해결이 필요한 경우 코드 `2`로 종료합니다. 스키마 불일치 시 코드 `3`으로 종료합니다. `--dry-run` 없이 실행하면 청크를 멱등적으로 스테이징하고, 실행을 적용하며, 최종 요약과 최근 진행 이벤트를 출력합니다.

## 개발

```bash
pnpm dev              # 전체 개발 환경 (API + UI, 감시 모드)
pnpm dev:once         # 파일 감시 없이 전체 개발 환경 실행
pnpm dev:server       # 서버만 실행
pnpm build            # 전체 빌드
pnpm typecheck        # 타입 검사
pnpm test             # 기본 테스트 실행 (Vitest만)
pnpm test:watch       # Vitest 감시 모드
pnpm test:e2e         # Playwright 브라우저 테스트 스위트
pnpm db:generate      # DB 마이그레이션 생성
pnpm db:migrate       # 마이그레이션 적용
```

`pnpm test`는 Playwright를 실행하지 않습니다. 브라우저 테스트 스위트는 별도로 유지되며, 해당 플로우 작업 시 또는 CI에서만 실행됩니다.

전체 개발 가이드는 [doc/DEVELOPING.md](https://github.com/paperclipai/paperclip/blob/master/doc/DEVELOPING.md)를 참조하세요.

## 텔레메트리

Paperclip은 제품이 어떻게 사용되는지 이해하고 개선하기 위해 익명 사용 텔레메트리를 수집합니다. 개인 정보, 이슈 내용, 프롬프트, 파일 경로, 시크릿은 절대 수집되지 않습니다. 프라이빗 저장소 참조는 전송 전에 설치별 솔트로 해시됩니다.

텔레메트리는 **기본적으로 활성화**되어 있으며 다음 방법 중 하나로 비활성화할 수 있습니다.

| 방법             | 방법                                                    |
| ---------------- | ------------------------------------------------------- |
| 환경 변수        | `PAPERCLIP_TELEMETRY_DISABLED=1`                        |
| 표준 관례        | `DO_NOT_TRACK=1`                                        |
| CI 환경          | `CI=true`일 때 자동으로 비활성화                        |
| 설정 파일        | Paperclip 설정에서 `telemetry.enabled: false`로 설정    |
