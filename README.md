# Paperclip은 사람들이 업무에서 AI 에이전트를 관리하는 데 사용하는 앱입니다.

AI 에이전트 팀을 위한 오픈소스 오케스트레이션 플랫폼입니다.

**OpenClaw이 _직원_이라면, Paperclip은 _회사_입니다.**

Paperclip은 AI 에이전트 팀을 오케스트레이션하여 비즈니스를 운영하는 Node.js 서버와 React UI입니다. 나만의 에이전트를 연결하고, 목표를 할당하고, 하나의 대시보드에서 작업과 비용을 추적합니다.

외관상 작업 관리자처럼 보입니다. 그 안에는 조직도, 예산, 거버넌스, 목표 정렬, 에이전트 조율이 담겨 있습니다.

**풀 리퀘스트가 아닌 비즈니스 목표를 관리합니다.**

|        | 단계            | 예시                                                            |
| ------ | --------------- | ------------------------------------------------------------------ |
| **01** | 목표 정의 | _"AI 메모 앱 1위를 달성해 월 매출(MRR) 100만 달러를 달성한다."_                    |
| **02** | 팀 구성   | CEO, CTO, 엔지니어, 디자이너, 마케터 — 어떤 봇이든, 어떤 프로바이더든. |
| **03** | 승인 및 실행 | 전략을 검토합니다. 예산을 설정합니다. 시작합니다. 대시보드에서 모니터링합니다.  |

## 이런 분께 Paperclip이 적합합니다

- ✅ **자율적인 AI 회사**를 구축하고 싶은 분
- ✅ 공통 목표를 향해 **다양한 에이전트**(OpenClaw, Codex, Claude, Cursor)를 **조율**하는 분
- ✅ **Claude Code 터미널을 20개** 동시에 열어두고 각자 무엇을 하는지 파악하기 힘든 분
- ✅ 에이전트가 **24/7 자율 운영**되길 원하지만 작업 감사 및 개입 기능도 필요한 분
- ✅ **비용을 모니터링**하고 예산을 집행하고 싶은 분
- ✅ 에이전트 관리 프로세스가 **작업 관리자처럼 느껴지길** 원하는 분
- ✅ **스마트폰에서** 자율 비즈니스를 관리하고 싶은 분

## Paperclip이 해결하는 문제들

| Paperclip 없이                                                                                                                     | Paperclip과 함께                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ Claude Code 탭을 20개 열어두고 어느 것이 무엇을 하는지 파악할 수 없습니다. 재부팅하면 모든 것을 잃습니다.                              | ✅ 작업은 티켓 기반이고, 대화는 스레드로 구성되며, 세션은 재부팅 후에도 유지됩니다.                                                |
| ❌ 봇에게 실제로 무엇을 하고 있는지 상기시키기 위해 여러 곳에서 수동으로 컨텍스트를 수집합니다.                                     | ✅ 컨텍스트는 작업에서 프로젝트, 회사 목표까지 흘러갑니다 — 에이전트는 항상 무엇을 왜 해야 하는지 알고 있습니다.                  |
| ❌ 에이전트 설정 폴더들이 정리되지 않고, 작업 관리, 커뮤니케이션, 에이전트 간 조율을 직접 재발명하고 있습니다. | ✅ Paperclip은 조직도, 티켓, 위임, 거버넌스를 기본 제공합니다 — 스크립트 더미가 아닌 회사를 운영하세요. |
| ❌ 무한 루프로 수백 달러의 토큰을 낭비하고, 무슨 일이 일어났는지 알기도 전에 할당량을 소진합니다.                           | ✅ 비용 추적으로 토큰 예산을 파악하고 초과 시 에이전트를 제한합니다. 관리자는 예산으로 우선순위를 정합니다.                    |
| ❌ 반복 작업(고객 지원, 소셜, 보고서)이 있어 수동으로 실행해야 할 것을 기억해야 합니다.                        | ✅ 하트비트가 정기 작업을 일정대로 처리합니다. 관리자가 감독합니다.                                                                |
| ❌ 아이디어가 생기면 저장소를 찾고, Claude Code를 켜고, 탭을 열어두고, 계속 지켜봐야 합니다.                                | ✅ Paperclip에 작업을 추가합니다. 코딩 에이전트가 완료할 때까지 작업합니다. 관리자가 작업을 검토합니다.                              |

## Paperclip이 특별한 이유

Paperclip은 복잡한 오케스트레이션 세부 사항을 올바르게 처리합니다.

|                                   |                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **원자적 실행.**             | 작업 체크아웃과 예산 집행은 원자적으로 처리되어 중복 작업과 예산 초과가 없습니다.                      |
| **영속적 에이전트 상태.**       | 에이전트는 처음부터 다시 시작하는 대신 하트비트 간에 동일한 작업 컨텍스트를 재개합니다.                     |
| **런타임 스킬 주입.**      | 에이전트는 재훈련 없이 런타임에 Paperclip 워크플로와 프로젝트 컨텍스트를 학습할 수 있습니다.                      |
| **롤백이 가능한 거버넌스.**     | 승인 게이트가 시행되고, 설정 변경에 버전이 관리되며, 잘못된 변경은 안전하게 롤백할 수 있습니다.        |
| **목표 인식 실행.**         | 작업에는 전체 목표 계층이 포함되어 에이전트가 제목만이 아닌 "이유"를 일관되게 파악합니다.                        |
| **이식 가능한 회사 템플릿.**   | 시크릿 제거 및 충돌 처리와 함께 조직, 에이전트, 스킬을 내보내기/가져오기합니다.                          |
| **진정한 멀티 회사 격리.** | 모든 엔티티는 회사 범위로 지정되므로 단일 배포로 별도 데이터 및 감사 추적이 있는 여러 회사를 운영할 수 있습니다. |

### 시스템 구성 요소

<table>
<tr>
<td width="50%">

**신원 및 접근** — 두 가지 배포 모드(신뢰된 로컬 또는 인증), 보드 사용자, 에이전트 API 키, 단기 실행 JWT, 회사 멤버십, 초대 플로우, OpenClaw 온보딩. 모든 변경 요청은 행위자로 추적됩니다.

</td>
<td width="50%">

**조직도 및 에이전트** — 에이전트에게는 역할, 직함, 보고 라인, 권한, 예산이 있습니다. 어댑터 예시는 다이어그램과 일치합니다: Claude Code, Codex, Cursor/Gemini/bash 같은 CLI 에이전트, OpenClaw 같은 HTTP/웹훅 봇, 외부 어댑터 플러그인. 하트비트를 수신할 수 있다면 채용된 것입니다.

</td>
</tr>
<tr>
<td>

**작업 및 작업 시스템** — 이슈에는 회사/프로젝트/목표/부모 링크, 실행 잠금이 있는 원자적 체크아웃, 일급 블로커 의존성, 댓글, 문서, 첨부 파일, 작업 산출물, 레이블, 받은 편지함 상태가 포함됩니다. 중복 작업 없음, 컨텍스트 손실 없음.

</td>
<td>

**하트비트 실행** — 병합, 예산 확인, 워크스페이스 해결, 시크릿 주입, 스킬 로딩, 어댑터 호출을 갖춘 DB 기반 웨이크업 큐. 실행은 구조화된 로그, 비용 이벤트, 세션 상태, 감사 추적을 생성합니다. 복구는 고아 실행을 자동으로 처리합니다.

</td>
</tr>
<tr>
<td>

**워크스페이스 및 런타임** — 프로젝트 워크스페이스, 격리된 실행 워크스페이스(git 워크트리, 운영자 브랜치), 런타임 서비스(개발 서버, 미리보기 URL). 에이전트는 매번 올바른 디렉터리에서 올바른 컨텍스트로 작업합니다.

</td>
<td>

**거버넌스 및 승인** — 보드 승인 워크플로, 검토/승인 단계가 있는 실행 정책, 결정 추적, 예산 하드 스탑, 에이전트 일시 정지/재개/종료, 전체 감사 로깅. 여러분의 승인 없이는 아무것도 배포되지 않습니다.

</td>
</tr>
<tr>
<td>

**예산 및 비용 통제** — 회사, 에이전트, 프로젝트, 목표, 이슈, 프로바이더, 모델별 토큰 및 비용 추적. 경고 임계값 및 하드 스탑이 있는 범위별 예산 정책. 초과 지출은 에이전트를 일시 정지하고 대기 중인 작업을 자동으로 취소합니다.

</td>
<td>

**루틴 및 스케줄** — cron, 웹훅, API 트리거가 있는 반복 작업. 동시성 및 따라잡기 정책. 각 루틴 실행은 추적된 이슈를 생성하고 할당된 에이전트를 깨웁니다 — 수동 실행이 필요 없습니다.

</td>
</tr>
<tr>
<td>

**플러그인** — 프로세스 외부 워커, 기능 게이트 호스트 서비스, 작업 스케줄링, 도구 노출, UI 기여가 있는 인스턴스 전체 플러그인 시스템. 포크 없이 Paperclip을 확장합니다.

</td>
<td>

**시크릿 및 스토리지** — 인스턴스 및 회사 시크릿, 암호화된 로컬 스토리지, 프로바이더 기반 객체 스토리지, 첨부 파일, 작업 산출물. 민감한 값은 범위 지정 실행이 명시적으로 필요하지 않는 한 프롬프트에서 제외됩니다.

</td>
</tr>

<td>

## Paperclip이 아닌 것

|                              |                                                                                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **챗봇이 아닙니다.**           | 에이전트에게는 채팅 창이 아닌 직무가 있습니다.                                                                  |
| **에이전트 프레임워크가 아닙니다.**  | 에이전트를 어떻게 구축해야 하는지 알려주지 않습니다. 에이전트로 이루어진 회사를 어떻게 운영하는지 알려줍니다.                                |
| **워크플로 빌더가 아닙니다.**  | 드래그 앤 드롭 파이프라인이 없습니다. Paperclip은 조직도, 목표, 예산, 거버넌스를 갖춘 회사를 모델링합니다.            |
| **프롬프트 관리자가 아닙니다.**    | 에이전트는 자체 프롬프트, 모델, 런타임을 가져옵니다. Paperclip은 에이전트가 일하는 조직을 관리합니다.               |
| **단일 에이전트 도구가 아닙니다.** | 이것은 팀을 위한 도구입니다. 에이전트가 하나라면 Paperclip이 필요 없을 것입니다. 20개라면 — 반드시 필요합니다. |
| **코드 리뷰 도구가 아닙니다.**  | Paperclip은 풀 리퀘스트가 아닌 작업을 오케스트레이션합니다. 리뷰 프로세스는 직접 가져오세요.                                       |

## 빠른 시작

오픈소스. 자체 호스팅. Paperclip 계정이 필요 없습니다.

```bash
npx paperclipai onboard --yes
```

> **문제 해결: 비공개 npm 레지스트리 `.npmrc`**
>
> `paperclipai`에 대한 `E404`(또는 유사한 오류)로 실패하고 글로벌 `~/.npmrc`를 통해 비공개 npm 레지스트리(예: GitHub Packages)를 사용하는 경우, `npx`가 공개 npm 레지스트리 대신 비공개 레지스트리에서 `paperclipai`를 찾으려 할 수 있습니다.
>
> 진단:
>
> ```bash
> npm config get registry
> ```
>
> 해결 방법 (크로스 플랫폼; 이 명령에만 공개 npm 레지스트리 강제 사용):
>
> ```bash
> npx --registry https://registry.npmjs.org paperclipai onboard --yes
> ```

이 빠른 시작 경로는 가장 빠른 첫 실행을 위해 기본적으로 신뢰된 로컬 루프백 모드를 사용합니다. 대신 인증/비공개 모드로 시작하려면 바인드 프리셋을 명시적으로 선택합니다:

```bash
npx paperclipai onboard --yes --bind lan
# 또는:
npx paperclipai onboard --yes --bind tailnet
```

Paperclip이 이미 설정되어 있다면, `onboard`를 다시 실행해도 기존 설정이 유지됩니다. 설정을 편집하려면 `paperclipai configure`를 사용합니다.

또는 수동으로:

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

이렇게 하면 `http://localhost:3100`에서 API 서버가 시작됩니다. 임베디드 PostgreSQL 데이터베이스가 자동으로 생성됩니다 — 별도 설정이 필요 없습니다.

> **요구 사항:** Node.js 20+, pnpm 9.15+

## 자주 묻는 질문

**일반적인 설정은 어떻게 생겼나요?**
로컬에서는 단일 Node.js 프로세스가 임베디드 Postgres와 로컬 파일 스토리지를 관리합니다. 프로덕션의 경우 자체 Postgres를 지정하고 원하는 방식으로 배포합니다. 프로젝트, 에이전트, 목표를 설정하면 — 에이전트가 나머지를 처리합니다.

1인 기업가라면 Tailscale을 사용해 이동 중에도 Paperclip에 접근할 수 있습니다. 이후 필요 시 예를 들어 Vercel에 배포할 수 있습니다.

**여러 회사를 운영할 수 있나요?**
네. 단일 배포로 완전한 데이터 격리를 갖춘 무제한 수의 회사를 운영할 수 있습니다.

**Paperclip은 OpenClaw이나 Claude Code 같은 에이전트와 어떻게 다른가요?**
Paperclip은 그 에이전트들을 _사용_합니다. 조직도, 예산, 목표, 거버넌스, 책임성을 갖춘 회사로 오케스트레이션합니다.

**OpenClaw을 Asana나 Trello에 연결하는 대신 Paperclip을 사용해야 하는 이유가 있나요?**
에이전트 오케스트레이션에는 작업을 누가 체크아웃했는지 조율하는 방법, 세션 유지 방법, 비용 모니터링, 거버넌스 확립 등 미묘한 점이 있습니다 — Paperclip이 이를 대신 처리합니다.

(나만의 티켓 시스템 연동은 로드맵에 있습니다)

**에이전트는 계속 실행되나요?**
기본적으로 에이전트는 예약된 하트비트와 이벤트 기반 트리거(작업 할당, @-멘션)로 실행됩니다. OpenClaw 같은 연속 에이전트를 연결할 수도 있습니다. 에이전트를 가져오면 Paperclip이 조율합니다.

## 개발

```bash
pnpm dev              # 전체 개발 (API + UI, 감시 모드)
pnpm dev:once         # 파일 감시 없는 전체 개발
pnpm dev:server       # 서버만
pnpm build            # 전체 빌드
pnpm typecheck        # 타입 검사
pnpm test             # 기본 테스트 실행 (Vitest만)
pnpm test:watch       # Vitest 감시 모드
pnpm test:e2e         # Playwright 브라우저 스위트
pnpm db:generate      # DB 마이그레이션 생성
pnpm db:migrate       # 마이그레이션 적용
```

`pnpm test`는 Playwright를 실행하지 않습니다. 브라우저 스위트는 별도로 유지되며 일반적으로 해당 플로우 작업 시 또는 CI에서만 실행됩니다.

전체 개발 가이드는 [doc/DEVELOPING.md](doc/DEVELOPING.md)를 참조하세요.

## 관측 가능성

Paperclip은 서버를 위한 옵트인 OpenTelemetry 자동 계측(트레이스만)을 제공합니다. `OTEL_EXPORTER_OTLP_ENDPOINT`가 설정되면 활성화되며, 표준 `OTEL_EXPORTER_OTLP_PROTOCOL` 환경 변수를 통해 `grpc`, `http/protobuf`, `http/json`을 지원합니다. `@opentelemetry/*` 패키지는 선택적 피어 의존성입니다 — 트레이싱이 필요한 경우에만 설치합니다. 설치 명령어와 전체 환경 변수 참조는 [doc/observability.md](doc/observability.md)를 참조하세요.

## 텔레메트리

Paperclip은 제품 사용 방식을 이해하고 개선하기 위해 익명 사용 텔레메트리를 수집합니다. 개인 정보, 이슈 내용, 프롬프트, 파일 경로, 시크릿은 절대 수집되지 않습니다. 비공개 저장소 참조는 설치별 솔트로 해시 처리되어 전송됩니다.

텔레메트리는 **기본적으로 활성화**되어 있으며 다음 중 하나로 비활성화할 수 있습니다:

| 방법               | 사용법                                                     |
| -------------------- | ------------------------------------------------------- |
| 환경 변수 | `PAPERCLIP_TELEMETRY_DISABLED=1`                        |
| 표준 규칙  | `DO_NOT_TRACK=1`                                        |
| CI 환경      | `CI=true`일 때 자동으로 비활성화됩니다.                   |
| 설정 파일          | Paperclip 설정에서 `telemetry.enabled: false` 설정 |
